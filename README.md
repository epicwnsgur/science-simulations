## 공통 구조

- `src/lab-shell.js`, `lab.css`: 실험 페이지 틀(활동 탭, 어두운 실험 무대, 관찰 기록, 스스로 평가, 핵심 개념)과 시각 효과(빛 번짐, 불꽃, 알림, 경로를 따라 흐르는 전자·물 알갱이).
- `theme-electric.css`: 전기와 자기 단원 공통 디자인(어두운 회로 기판 배경, 전류는 하늘색·전압은 노란색·자석은 빨강/파랑, 빛나는 버튼과 무대). 모든 실험이 마지막에 불러옵니다. 단원 페이지는 `unit-electric.css`를 씁니다.
- `src/poe-flow.js`: 예상하기 → 관찰하기 → 설명하기 흐름. 실험마다 관찰 체크리스트를 모두 마쳐야 설명 단계로 넘어갑니다.
- **PDF로 저장:** 보고서 제출 버튼 옆의 [PDF로 저장]은 같은 보고서(학생 정보, 실험별 예상·관찰·설명, 사용 후기)를 흰 바탕 A4 인쇄용으로 만들어 브라우저 인쇄 창을 엽니다. 대상에서 ‘PDF로 저장’을 고르면 됩니다(크롬은 파일 이름이 `실험 이름 탐구 보고서_학번_이름`). 학번·이름을 아직 안 적었으면 빈칸으로 둬 손으로 쓸 수 있습니다. 서버로는 보내지 않습니다.
- `src/report-submit.js`, `apps-script/Code.gs`: 개념 확인 아래의 ‘선생님께 보고서 제출하기’(학번·이름 두 번 입력 확인, 퀴즈 결과는 보내지 않음). `src/submission-config.js`에 Apps Script 웹 앱 주소를 넣으면 나타나고, 학생 보고서가 선생님 구글 시트의 실험별 탭에 반별로 모여 쌓입니다(학번 5자리의 2~3번째 자리 = 반). 설정 순서는 [`docs/google-sheet-submission.md`](docs/google-sheet-submission.md)를 보세요.
- `src/*-model.js`: 실험별 모형과 `node --test`로 확인하는 단위 테스트.
- **실험 전용 CSS 주의:** 배포(빌드)하면 실험 전용 CSS(예: `induction.css`)가 공통 CSS보다 나중에 읽혀요. 공통 CSS에 있는 선택자를 실험 전용 파일에서 다시 쓰면 어두운 테마를 덮어써 글씨가 안 보일 수 있어서(정전기 유도 설명하기의 안내 상자 사례), `src/css-scope.test.js`가 이를 막아요.
- `vite.config.js`는 `simulations/` 아래 폴더를 자동으로 빌드에 넣습니다. 새 실험은 폴더를 만들고 `netlify.toml` 리다이렉트와 단원 카드만 추가하면 됩니다.
- **실험 전 1분 복습(모든 실험 필수):** `src/reviews.js`에 실험마다 초등학교·지난 차시와 이어지는 질문 2~4개를 둡니다. 모든 질문에 답해야 ‘복습 마치고 실험 시작하기’가 켜지며 건너뛸 수 없습니다. 새 실험을 추가할 때 복습(`src/reviews.js`)과 퀴즈(`src/concept-quizzes.js`)를 함께 넣어야 하고, 빠지면 `npm test`가 실패해 알려 줍니다.
- **모든 실험에 공통으로 적용되는 학습 흐름(`src/poe-flow.js`, 새 실험도 자동 적용):**
  - **뒤로 가기:** 화면 순서(복습 → 실험 1 예상·관찰·설명 → 실험 2 …)에서 한 칸씩 돌아가요. 단계 줄 왼쪽과 ‘다음’ 버튼 옆에 있고, 브라우저·휴대폰의 뒤로 가기도 같은 방식으로 움직여요(첫 화면에서는 실험 목록으로 나가요). 쓴 글은 그대로 남아요.
  - **예상 확인 창:** ‘예상 저장하고 실험하기’를 누르면 고른 예상과 까닭을 보여 주며 ‘저장하면 고칠 수 없다’고 알려 줘요. ‘다시 고치기’ 또는 ‘확인했어요’를 골라요.
  - **순서 지키기:** 실험이 여럿이면 앞 실험을 설명까지 마쳐야 다음 실험이 열려요. 관찰하기에서는 ‘실험 순서 안내’의 앞 단계를 해야 다음 단계의 조작이 열리고(🔒), 잠긴 조작을 누르면 지금 할 일을 알려 줘요. 새 실험은 `checklist([[이름, 완료 여부, 하는 방법, '그 단계에서 처음 쓰는 조작의 CSS 선택자'], …])`처럼 넷째 값만 적으면 돼요. 한 번 관찰을 마친 실험은 모두 열려 자유롭게 다시 해 볼 수 있어요.
  - **실험 순서 가리키기:** 실험 단계를 다 하지 않고 ‘관찰 저장하고 설명하기’나 위쪽 ‘설명하기’를 누르면 넘어가지 않고, ‘실험 순서 안내를 보고 ○○부터 해 보세요’라는 안내와 함께 실험 순서 안내가 반짝이며 👉로 지금 할 단계를 가리켜요. 그 단계에서 쓸 조작에는 ‘👆 여기부터!’ 표시가 잠깐 붙어요. 예상하기에서 관찰하기를 누르면 ‘예상 저장하고 실험하기’를 가리켜요.
  - **단계를 누르면 할 일 알려 주기:** 실험 순서 안내의 단계를 누르면 그 단계를 하는 방법을 알려 주고, 지금 눌러야 할 단추에 ‘👆 여기를 눌러요’를 표시해요. 단추는 안내 글(`checklist`의 셋째 값)에 ‘ ’로 감싼 단추 이름으로 찾아요(이미 고른 탭·단추와 누를 수 없는 단추는 건너뛰어요). 이름이 없는 조작(그림의 스위치 등)은 다섯째 값에 CSS 선택자를 적어요. 새 실험도 단추 이름을 ‘ ’로 감싸 적으면 자동으로 돼요.
  - **교사 모드(`src/teacher-mode.js`):** 실험 첫 화면 위쪽 오른편의 ‘👩‍🏫 교사용’ → 비밀번호를 넣으면 켜져요. 복습을 건너뛰고 예상·관찰·설명 단계를 자유롭게 오가며(글을 쓰지 않아도 넘어가요), 관찰 단계의 순서 잠금·다음 실험 잠금이 모두 풀리고, 개념 정리도 바로 보여요. 같은 탭에서는 다른 실험으로 옮겨도 켜져 있고, 탭을 닫거나 ‘교사 모드 끄기’를 누르면 꺼져요. 비밀번호는 코드에 SHA-256 값으로만 들어 있어요(학생이 실수로 켜는 것을 막는 가벼운 잠금이에요).
  - **임시 저장(`src/draft-store.js`):** 쓰는 즉시 저장해서 새로 고침하거나 창을 닫았다가 다시 열어도 글이 돌아와요. 함께 쓰는 컴퓨터를 위해 이 컴퓨터에 남긴 글은 3시간 뒤 버리고, 제출하면 지워요. 되살린 글이면 위쪽에 알리고 ‘내 글이 아니에요 · 새로 시작’을 보여 줘요.
  - **글 지키기(`src/text-guard.js`):** 예상·관찰·설명·사용 후기 칸은 붙여 넣기·끌어다 놓기가 되지 않아요(교사 모드에서는 돼요). ‘ㅋㅋㅋ’·같은 말 되풀이·앞 칸과 똑같은 글·흔한 욕설은 저장하지 않아요. 같은 규칙을 `apps-script/Code.gs`도 한 번 더 확인해요. 글자 수는 글자와 숫자(㉮·① 같은 동그라미 글자 포함)만 세고, 글자 수 안내(✔ 좋아요)와 저장 검사가 같은 수를 써요.
  - **관찰 기록 칸 나누기:** 활동이 여럿인 실험은 관찰하기의 기록 칸을 활동마다 나눠요(실험의 `observe.parts: [{ title, label, placeholder }]`). 칸마다 20자 이상 쓰고, 저장하면 ‘[활동 이름] 글’로 이어 붙여 한 관찰 기록으로 보내요.
  - **내 메모(`src/memo.js`):** 오른쪽 아래 ‘📝 메모’ 단추로 언제든 열어 떠오른 생각·궁금한 점·측정값을 적어 둬요. 실험마다 따로 바로 저장되고(이 컴퓨터에 3시간), 보고서에는 들어가지 않아요.
  - **테마 바꾸기(`src/theme.js`, `theme-light.css`):** 머리글의 ‘🌸 밝은 테마 / 🌙 어두운 테마’ 단추로 어두운 테마(기본)와 핑크 밝은 테마를 오가요. 모든 페이지에서 기억해요. 밝은 테마 CSS는 `node build/light-theme.mjs`가 어두운 테마 CSS에서 만들어요(공통 CSS를 고치면 다시 실행하고, `npm test`가 최신인지 확인해요). 실험 무대 그림과 과학의 약속 색(N극 빨강·S극 파랑, 전하 색)은 바꾸지 않아요.
  - **실험 전 1분 복습:** 모든 질문에 답한 뒤 ‘정답 확인하기’를 눌러야 맞고 틀림과 해설이 나와요(마지막 퀴즈와 같아요). 확인한 뒤에는 답을 바꿀 수 없어요.
  - **보고서 미리보기·PDF:** 칸마다 학생이 답한 질문을 함께 넣어요.
  - **실험 미리 보기(`src/previews.js`, `src/preview-scenes.js`):** 예상 단계에서 어떤 실험을 하는지 3~4단계로 보여 줘요. 단계마다 간단한 움직이는 그림(모션 그래픽)이 과정을 보여 주고, 단계를 누르면 그 움직임을 다시 봐요. 결과는 보여 주지 않고 결과가 나올 자리에는 ‘?’를 띄워요. 새 실험을 만들면 두 파일에 함께 더해요.
  - **꼭 봐야 하는 보기:** ‘전하 보기’처럼 꺼져 있는 보기는 실험 순서 안내의 단계로 들어가, 켜고 현상을 봐야 다음으로 넘어가요.
  - **개념 포스트잇:** 개념 정리의 노란 글씨(주요 개념)는 📌 포스트잇으로 가려져 있고, 모두 떼어야 보고서를 제출할 수 있어요. 하나를 떼면 1초 동안 떨어지며 개념이 나타나고, 1초를 더 기다려야 다음 것을 뗄 수 있어요(읽지 않고 연달아 누르지 않게).
  - **화면 크기:** 위쪽 ‘화면 크기 − / +’로 페이지 전체를 67~125%로 줄이고 키워요(Ctrl −/+ 와 같아요). 다른 실험에서도 기억해요.
  - **전류와 전압 3D 수로 모형(`src/water-3d.js`):** 펌프가 만든 물의 높이 차(= 전압)를 3D로 보여 주고, 전기 회로와 수로 모형의 짝 5개를 찾아 두 그림에 같은 색으로 표시해요.
  - **과학 낱말 뜻 풀이(`src/glossary.js`):** 복습·예상·실험 안내·관찰 안내·개념 정리·퀴즈 글에 나오는 주요 과학 낱말(전류, 전압, 저항, 자기장, 정전기 유도 등 32개, 중학교 2학년 교과서 낱말로 풀이)에 점선 밑줄이 생기고, 누르면 쉬운 뜻이 말풍선으로 나와요(바깥을 누르거나 Esc로 닫혀요). 답을 고르는 단추 안에는 붙이지 않아요. 새 낱말은 `TERMS`에 더하면 모든 실험에 적용돼요.
  - **퀴즈:** 고른 보기는 어두운 바탕·노란 테두리와 ‘● 내 선택’ 표시로 또렷하게 보이고, 결과를 본 뒤에도 ‘내 답 · 정답/오답’, 고르지 않은 정답에는 ‘정답’ 표시가 남아요.
- **부드러운 움직임(`src/lab-shell.js`, 공통 CSS):** 끌 수 있는 물체는 `smoothDrag`로 손가락·마우스·방향키를 매끄럽게 따라오고(마찰 전기·정전기 유도·전류가 만든 자기장), 화면 전환·버튼·진행 막대에 짧은 전환 효과를 넣었어요. ‘동작 줄이기’ 설정을 켠 기기에서는 효과를 빼요. 새 실험의 끌기도 `smoothDrag`를 쓰세요.
- **자동 재생(`src/autoplay.js`):** 핵심 과정을 단계별로 보여 주는 공통 부품이에요. 자동 재생 중에는 가상 시계가 보통 0.6배, 천천히 0.4배로 흘러 움직임·기다림이 함께 느려지고, 일시정지하면 멈춰요(빠르기를 바꾸면 바로 적용). 지금은 마찰 전기에서 쓰고, 새 실험은 `createAutoplay`와 `player.clock()`으로 붙일 수 있어요.

## 3~8번 실험의 근거와 범위

- **전류와 전압:** 마찰 전기로 네온전구를 순간적으로 켜고, 다시 대면 켜지지 않음을 확인합니다. 전지 회로에서 전자는 (−)극→(+)극, 전류는 (+)극→(−)극으로 표시하고, 전구로 들어간 전자와 나온 전자 수가 같음을 셉니다. 수로 모형의 한계를 화면에 안내합니다(지도서 555쪽).
  - 그림은 실제 기구처럼 그렸어요: 털가죽, 플라스틱 접시, 절연 손잡이가 달린 알루미늄 접시, 유리관 속 두 전극이 보이는 네온전구, 1.5 V 건전지, 유리구·필라멘트·소켓이 있는 전구, 피복 전선, 펌프·관·물레방아.
- **전압, 전류, 저항:** 지도서 561쪽 결과(긴 니크롬선 1 V당 50 mA, 짧은 니크롬선 100 mA)를 사용해 표와 그래프를 그립니다. 스위치를 오래 닫으면 니크롬선이 달아오르며 경고합니다. 도체·부도체 분류 활동을 포함합니다.
- **저항의 연결:** 같은 전구 두 개만 다루고 계산·혼합 연결은 다루지 않습니다(지도서 566쪽). 밝기를 회로 카드처럼 1~3칸으로 칠합니다.
- **전류가 만든 자기장:** 나침반 8개와 움직일 수 있는 나침반으로 관찰합니다. 바늘은 지구 자기장과 합쳐진 방향을 가리킵니다. 스위치는 누르는 동안만 전류가 흐릅니다. ‘자기력선’ 용어는 쓰지 않습니다(지도서 586쪽).
  - **나침반과 전선:** 둘레 나침반 8개가 교과서 그림처럼 자기장 모습(선)의 방향을 거의 따르도록 코일·자석과 지구 자기장의 세기 비율을 정했어요(막대자석 10° 안팎, 코일 ‘보통’ 10° 안팎·‘세게’ 5° 안팎·‘약하게’ 20°쯤 어긋남). 전원 장치의 (+)극·(−)극에서 코일까지 전선을 그렸고, ‘전류 방향 바꾸기’를 누르면 두 전선을 바꾸어 꽂은 모습이 돼요. 전류가 흐르면 전선 위로 노란 무늬(3D는 알갱이)가 전류의 방향으로 흐르고, 판을 뚫는 두 곳에 ⊙(판 위로 나옴)·⊗(판 아래로 들어감)가 표시돼요.
  - **3D 보기:** 코일이 투명한 판을 뚫고 서 있는 모습, 판 위 나침반, 판 위와 코일(자석) 둘레 공간의 자기장 모습을 입체로 보여 줍니다. ‘비스듬히·옆에서·위에서’ 시점이 있고 ‘위에서’는 2D 그림과 같습니다. 노란 나침반은 3D 화면에서도 끌어서 옮기고, 방향키로도 옮길 수 있습니다.
  - **과학 검증:** 자기장은 `src/field3d.js`에서 3차원으로 계산합니다(코일은 비오-사바르 법칙으로 감은 줄 5개를 잘게 나누어 더하고, 막대자석은 양 끝면의 자극). 2D 그림의 바늘·선도 같은 계산을 씁니다. `src/field3d.test.js`는 원형 코일 공식과의 일치, 판을 뚫는 도선 둘레의 오른손 법칙, 전류 방향·세기에 따른 변화, 막대자석의 N→S, 자기장 모습 선의 방향을, `tests/coil3d.spec.js`는 화면에 그려진 바늘과 화살표가 그 자리의 (지구 + 코일·자석) 자기장 방향과 같은지 확인합니다.
- **전기 그네:** 처음 상태에서 바깥쪽(㉮), 전류나 극 중 하나를 바꾸면 안쪽(㉯)으로 움직입니다(지도서 592쪽). 전압이 클수록 많이 움직입니다.
  - **3D 보기(`src/swing-3d.js`):** 말굽자석의 두 팔 사이를 지나는 코일 아래 변, 뒤쪽 기둥에 매단 그네, 전원 장치와 전선을 입체로 보여 줘요(‘비스듬히·앞에서·옆에서’). 전류의 방향을 바꾸면 두 전선을 바꾸어 꽂은 모습이 돼요. 힘은 `src/swing-physics.js`에서 F = IL×B로 구하고(세로 변은 자기장과 나란해 힘이 0), `src/swing-physics.test.js`와 `tests/swing3d.spec.js`로 2D 모형·화면의 화살표와 같은지 확인해요.
- **3D 실험 공통 부품:** `src/three-kit.js`(장면·카메라·시점 옮기기·화질 자동 조절·이름표·화살표)와 `src/view-toggle.js`(3D/2D 보기 단추, WebGL이 없으면 2D)를 함께 씁니다. 새 3D 실험은 장면(물체)만 만들면 됩니다.
- **전동기:** 그림 Ⅶ-16을 앞에서 본 모습으로 코일 두 변의 힘을 보여 주고, 간이 전동기(264쪽)에서 에나멜을 반만 벗긴 경우와 모두 벗긴 경우를 비교합니다.
  - **3D 보기(three.js):** 전동기의 원리와 간이 전동기를 입체로 보여 줍니다. 화면을 끌어 돌려 보고 ‘비스듬히·축을 따라·위에서’ 시점으로 부드럽게 옮겨 갈 수 있습니다. ‘축을 따라’는 2D 그림(앞에서 본 모습)과 같은 방향입니다. ‘2D 그림’ 단추로 언제든 바꿀 수 있고, 고른 보기는 기기에 기억됩니다. WebGL을 쓸 수 없는 기기는 자동으로 2D 그림을 씁니다.
  - **과학 검증:** 화살표 방향은 `src/motor-physics.js`에서 F = IL×B로 직접 계산합니다. 자기장은 N극→S극, 두 변의 전류·힘은 서로 반대, 정류자(금색 고리)는 코일이 세로로 설 때 전류 방향을 바꾸고, 간이 전동기는 벗긴 쪽이 받침대에 닿는 반 바퀴 동안만 전류가 흐릅니다. 이 계산이 회전 모형(`src/force-model.js`)과 같은 방향인지 `src/motor-physics.test.js`, 화면에 그려진 화살표가 F = I×B를 따르는지 `tests/motor3d.spec.js`로 확인합니다.
  - **부드러운 움직임:** 움직임이 없으면 다시 그리지 않고, 프레임이 느려지면 해상도와 반사 표현을 단계적으로 낮춥니다. 3D 코드는 3D 실험 페이지를 열 때만 따로 불러옵니다.
- 모든 수치·속도·각도는 정성적 비교를 위한 화면 표현입니다.

## VIII. 별과 우주 (5개 실험)

교과서·교사용 교과서·지도서의 지도상 유의점에 맞춰 만들었어요. 별까지의 거리를 구하는 **수식은 쓰지 않고**(연주 시차·겉보기 등급·절대 등급의 개념 중심), 별의 표면 온도는 **색으로 비교하는 수준**만 다루며, **적색 편이·허블 법칙·가속 팽창은 다루지 않아요.** 계산(`src/space-model.js` 등)은 그림이 실제와 맞도록 화면 뒤에서만 써요.

- **수업 모형(`src/teaching-models.js`):** 별 실험 3개는 POE(예상–관찰–설명), 우리은하는 지도서가 제안한 **발생 학습 모형**(예비 → 초점 → 도전·적용), 우주 팽창은 **비유를 활용한 수업 모형(FAR)**(초점 → 실행 → 반성)이에요. 모형에 따라 단계 이름과 안내 문구만 바뀌고, 학생 답은 똑같이 예상(처음 생각)·까닭·관찰(탐구 기록)·설명 네 칸으로 Apps Script에 모여요. 보고서에는 `model`과 `fieldLabels`가 함께 가서, 새 Apps Script는 모형에 맞는 칸 이름으로 시트 머리글을 만들어요(예전 Apps Script도 그대로 저장돼요).
- **실제 밤하늘(`src/sky-render.js`):** 스텔라리움처럼 실제 별(HYG 별 목록 v4.1, 6등급까지 약 5000개)의 위치·밝기·색(색지수)과 별자리 선·은하수 윤곽(d3-celestial)으로 하늘을 그려요. 자료는 `build/make-space-data.py`로 만든 `src/data/*.js`예요.
- **실제 천체 사진(`public/space/`, `src/space-photos.js`):** ESO·NASA/ESA·NOIRLab·위키미디어 공용의 출처가 분명한 사진만 쓰고, 실험마다 ‘사진과 자료 출처’에 적었어요. 은하 붙임딱지·배경 은하는 허블 익스트림 딥 필드에서 오려 냈어요.
- **별까지의 거리와 연주 시차(POE):** ① 교과서 277쪽 시차 측정 판(두 구멍으로 본 위치 ⑧④ / ⑥⑤, 각도기로 잰 시차 약 37° / 19°) ② 3D 지구 공전 모형과 ‘지구에서 본 하늘’ 창(별 X가 X1→X2로, 먼 별 Y는 조금만 움직임, ‘지구가 공전하지 않는다면?’) ③ 실제 별(프록시마 4.2 광년 0.77″ … 북극성·베텔게우스는 100 pc보다 멀어 재기 어려움).

- **별 하나하나의 실제 사진(`public/space/stars`, `src/star-viewer.js`):** 리겔·스피카·베가·카펠라·아크투루스·알데바란·베텔게우스(디지털 하늘 탐사 사진), 안타레스(넓게 찍은 사진), 시리우스(허블), 태양(SDO)의 실제 사진을 ‘사진 관측 창’에서 봐요. 사진이 흐릿하게 나타났다가 초점이 맞고, 끌어서 둘러보기·확대할 수 있어요. ‘별빛 색 재기’는 별 둘레의 빛(가운데 넘친 곳은 빼고)을 모아 색을 보여 줘요(푸른 별 리겔·스피카·베가 → 푸른빛, 베텔게우스·알데바란·아크투루스·안타레스 → 붉은빛). 베텔게우스와 안타레스는 초대형 망원경(VLT·VLTI)으로 찍은 별 표면 사진까지 부드럽게 확대돼요. 실제 사진이 없는 별(나오스·알타이르·프로키온)만 관측 자료로 그려요.

### 활동

- **01 쇠숟가락 움직이기 (해 보기, 238쪽):** 추를 올린 쇠숟가락의 손잡이 끝에 대전되지 않은 빨대, 털가죽으로 문질러 (−)전하를 띤 빨대, 빨대와 문질러 (+)전하를 띤 장갑을 가까이 합니다. (−)빨대는 전자를 먼 쪽으로 밀어내고 (+)장갑은 전자를 가까운 쪽으로 끌어당겨, 두 경우 모두 가까운 쪽에 대전체와 다른 종류의 전하가 유도되어 숟가락이 추를 중심으로 대전체 쪽으로 돌아갑니다. 대전되지 않은 빨대에는 반응하지 않습니다.
- **02 검전기 관찰하기 (탐구, 240–241쪽):** 빨대·풍선(털가죽과 문지름, (−))과 장갑(빨대와 문지름, (+))을 고르고 문지르지 않음 / 2~3번 / 10번 이상 중 하나를 골라 금속판에 가까이 합니다. 금속판에는 대전체와 다른 종류, 금속박에는 같은 종류의 전하가 유도되어 두 금속박이 척력으로 벌어집니다. 많이 문지를수록, 가까울수록 더 많은 전자가 금속 막대를 따라 이동해 더 많이 벌어집니다.
- **관찰 조건:** (−)빨대와 (+)장갑으로 각각 숟가락 움직이기, 검전기에 2~3번과 10번 이상 문지른 물체 가까이 하기. 네 가지를 모두 해야 설명 단계로 넘어갑니다.
- **설명 단계:** 정전기 유도 과정, 대전체 종류와 관계없이 인력이 작용하는 까닭, 검전기 원리를 정리하고 스스로 평가 두 문항(241쪽)과 핵심 용어(정전기 유도, 검전기, 대전체, 전기력, 인력, 척력)를 제공합니다.

### 교육과정 범위와 모형

- 금속 안에서 **전자만** 이동하고 원자핵은 제자리에 있습니다(지도상 유의점: 정전기 유도를 (−)전하를 띤 전자의 이동으로 설명).
- 대전체는 금속에 **닿지 않습니다.** 끌기·버튼·키보드 모두 일정 거리 밖에서 멈추고, 숟가락도 닿기 전에 멈춥니다(지도상 유의점: 대전된 물체가 금속 물체에 닿는 상황은 다루지 않음). 접촉 대전, 손가락 접지로 검전기 전체를 대전시키기 같은 지도서 보충 설명은 넣지 않았습니다.
- 빨대·풍선·장갑 같은 부도체 안의 전하 재배치(유전 분극)는 다루지 않으므로 그리지 않습니다. 대전체에는 교과서 그림처럼 대전된 만큼 남는 전하만 표시합니다.
- 오개념(교사용 교과서 239쪽, 지도서 547쪽) 대응: 전자가 가장 많이 몰려도 가까운 쪽과 먼 쪽, 금속판과 금속박에 두 종류의 전하가 모두 남습니다. 설명 단계에서 "가까운 쪽에 (+)전하만 있는 것은 아니며 상대적으로 많아진 것"임을 짚습니다.
- 숟가락은 인력에 의한 돌림힘이 바닥 마찰보다 클 때만 돌고, 대전체를 멀리 해도 끌려온 자리에 남습니다. 전하 분포는 대전체가 멀어지면 원래대로 돌아갑니다.
- 입자 수, 이동 거리, 금속박 각도, 거리에 따른 반응은 보기 쉽게 나타낸 정성적 표현이며 측정값이나 정량 관계(쿨롱 법칙 등)를 뜻하지 않습니다.
- 풍선 그림은 마찰 전기 실험의 `public/images/balloon-fur.png`를 다시 사용합니다. 숟가락·검전기·빨대·장갑은 SVG로 직접 그렸습니다.

### 근거 및 범위

사용자가 제공한 교과서 PDF의 인쇄 236–237쪽, 교사용 교과서 237쪽 오개념 지도, 지도서 인쇄 540–543쪽, 과학과 교육과정 인쇄 52–53쪽의 [9과14-01] 중 마찰 전기 내용을 참고했습니다. 삽화는 웹앱을 위해 별도 제작했습니다.

## 메인 페이지와 실험 폴더

`/`는 준혁T의 과학 실험실 메인 화면입니다. ‘중학교 2학년 과학’ 폴더를 열면 `/grades/middle-school-2/`에서 8개의 단원 폴더를 볼 수 있습니다. `unit-7/`(VII. 전기와 자기)에 8개의 실험이 있습니다. 카드 탭은 모두 ‘실험’으로 표시합니다. 마찰 전기는 `/simulations/friction-electricity/`로 연결되며, 상단의 ‘← 실험 목록’으로 7단원 폴더에 돌아올 수 있습니다.

`index.html`과 `home.css`가 메인 화면을 담당하며, `style.css`·`poe.css`·`lab.css`는 실험 화면에서 사용합니다. Vite 다중 페이지 빌드로 각 주소의 HTML을 실제 생성하므로 GitHub Pages 하위 경로와 Netlify에서 직접 접속·새로고침이 가능합니다. 학생이 쓴 예상·관찰·설명은 페이지 메모리에만 있고 새로고침하면 사라집니다.

### 폴더와 실험 개수 자동 집계

`build/catalog.js`가 각 목록의 `a.folder` 링크를 따라 집계하며 Vite 개발 서버와 프로덕션 빌드에 적용됩니다. 폴더 수는 바로 아래 학년·단원 폴더 수, 실험 수는 모든 하위 폴더의 서로 다른 실험 URL 수입니다. 준비 중 카드(`article.future-folder`)는 실험 수와 별도로 표시합니다.

실험을 추가할 때 `simulations/<이름>/index.html`을 만들고 원하는 단원 목록에 기존 형식의 실험 카드 링크를 추가하세요. 학년·단원 폴더도 `grades/` 아래에 페이지를 만들고 상위 목록에 `a.folder` 링크를 추가하면 됩니다. 새 페이지는 빌드에 자동 포함되고, 다음 배포에서 모든 상위 개수가 갱신됩니다. 목록에 연결되지 않은 파일은 학생이 접근하는 목록의 실험 수에 포함하지 않습니다. 중복 링크는 한 번만 세며, 존재하지 않는 페이지 연결이나 순환 폴더 연결은 빌드 오류로 알립니다.

과학적 검토 결과와 교육용 모형의 한계는 [과학 검토 기록](docs/scientific-review.md)을 참고하세요.

### 모든 실험의 마지막 개념 확인 퀴즈

POE의 설명 작성과 개념 확인 이후, 마지막에 **OX 2문제 + 정답이 하나인 5지선다 3문제**를 제공합니다. 공통 `src/poe-flow.js`가 퀴즈 표시·재시작 초기화를 연결합니다. 고르는 동안에는 정답을 알려 주지 않고, 모두 고른 뒤 **결과 확인하기**를 누르면 점수와 문항별 내 답·정답·해설(오답이면 그 답이 틀린 까닭)을 보여 주며 다시 풀 수 있습니다. 답은 이 탭에만 기억되고 교사에게 전송되지 않습니다.

새 실험도 `setupPOEFlow`를 사용하고 `src/concept-quizzes.js`에 URL 폴더 이름을 키로 문제 3개를 등록하세요. 각 문제에는 `type`, `question`, `options`(ID·보기 쌍), `answer`(정답 ID), `explanation`을 작성합니다. 첫 두 문제는 `type: 'ox'`, 보기 `[['O','O'],['X','X']]`; 마지막은 `type: 'choice'`, 서로 다른 보기 5개입니다. 공통 형식 검증과 `npm test`가 등록 누락을 검사합니다. 다른 단원에서 직접 구성할 때는 `setupPOEFlow({ quiz: [...], ... })`로 같은 형식의 문제를 전달할 수도 있습니다. 이 경우에도 테스트의 실험 목록 검사에 해당 등록 방식을 반영하세요. 새 실험의 문제 내용은 교과서에 맞게 별도로 작성해야 합니다.
