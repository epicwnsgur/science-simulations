# 기획 먼저(plan-first)

obra/superpowers의 brainstorming, writing-plans, verification-before-completion 스킬에서 이 저장소에 맞는 부분만 골라 한국어로 옮겼어요(MIT, LICENSE-superpowers).
원본의 자동 실행 훅, 하위 에이전트, git worktree, 영어 계획서 파일은 쓰지 않아요.

## 먼저 판단해요: 요청에 다 들어 있나?

- **다 들어 있으면**(예: "제목 글꼴을 주아로"): 이 스킬을 쓰지 않고 바로 해요.
- **중요한 것이 빠져 있으면**(예: "밀도 실험 만들어 줘"): 아래 순서를 따라요.

## 순서

1. **먼저 살펴봐요.** 묻기 전에 저장소에서 답을 찾아요. `CLAUDE.md`, 같은 단원의 실험, `src/poe-flow.js`, `src/challenges.js`, `docs/scientific-review.md`를 읽어요. 저장소가 이미 답하는 것은 묻지 않아요.
2. **한 번에 질문 하나.** 선생님의 말로, 답에 따라 무엇이 달라지는지 함께 말해요. 보기 목록을 길게 붙이지 않아요. 예: "학생들이 직접 물체를 골라 넣게 할까요, 정해진 물체 세 개로 비교하게 할까요? 앞쪽이면 측정 칸이 더 필요해요."
   - 질문을 원하지 않는 것 같으면 한 줄 덧붙여요: "바로 만들어 보길 원하시면 그렇게 말씀해 주세요."
3. **기획을 짧게 보여줘요**(한국어, 한 화면 분량). 저장소에 파일로 남기지 않고 대화로 보여요.
   - 무엇을 배우나: 성취기준에 맞는 핵심 개념 한두 줄
   - 학습 흐름: 복습 → 예상 → 관찰 → 설명(`setupPOEFlow`)과 각 단계에서 학생이 하는 일
   - 화면 구성: 무대에 무엇이 보이고 무엇을 조작하나(필요하면 그림이나 화면 미리 보기를 함께 보여요)
   - 과학 검토에서 조심할 점: 오개념이 생길 수 있는 표현과 값(`docs/scientific-review.md` 절차)
   - 도전 과제 2~3개와 생각 더하기 1개
   - 만드는 방법이 둘 이상이면 두세 가지를 견주고, 하나를 권하며 까닭을 말해요.
   - 선생님이 말한 것과 제가 채운 것을 구별해요. 제가 채운 것은 "제안"이라고 써요.
4. **확인을 받아요.** "고칠 곳이나 빠진 것이 있을까요?"로 끝내고, 승인받은 뒤에 만들어요.
5. **만들 때는 작은 단계로.** 계산 법칙 검사(`src/*.test.js`)를 먼저 쓰고, 화면을 만들고, 단계마다 검사를 돌려요.

## 끝났다고 말하기 전에(증거 먼저)

- "통과했어요", "고쳤어요", "됐어요"라고 말하기 전에 그 말을 증명하는 명령을 **이번에 새로** 돌리고 결과를 읽어요.
  - 단위 검사: `npm test`, 빌드: `npm run build`, 화면 검사: 바꾼 실험의 `npx playwright test tests/<실험>.spec.js`
- 돌리지 못한 검사는 돌리지 못했다고, 실패한 검사는 실패했다고 그대로 말해요.
- 화면을 바꿨으면 스크린숏을 찍어 직접 보고, 선생님께도 보여 드려요.
