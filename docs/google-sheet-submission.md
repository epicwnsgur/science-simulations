# 학생 보고서를 구글 시트로 받기

학생이 실험을 마치고 **[제출하기]** 를 누르면 예상·관찰·설명이 선생님 구글 시트에 한 줄로 쌓입니다. 실험마다 실험 이름으로 탭이 저절로 생기고, 탭 안에서는 **반별로 모여** 색이 칠해집니다. 퀴즈는 학생 스스로 확인하는 활동이라 보내지 않습니다.

```
실험 페이지 ──(제출하기)──▶ Apps Script 웹 앱 ──▶ 선생님 구글 시트
                            · 수업 코드 확인          ├ 설정 (수업 코드, 제출 받기)
                            · 명단 확인(선택)          ├ 명단 (학번, 이름)
                                                       ├ 옴의 법칙
                                                       └ 전기 그네 …
```

## 1. 구글 시트 만들기

1. 선생님 구글 계정으로 [sheets.new](https://sheets.new)를 열어 새 시트를 만들고 이름을 정합니다. 예: `2학년 전기와 자기 보고서`
2. 메뉴에서 **확장 프로그램 → Apps Script**를 누릅니다.

## 2. 코드 붙여 넣고 처음 실행하기

1. 열린 편집기의 `Code.gs`에 있던 내용을 모두 지우고, 저장소의 [`apps-script/Code.gs`](../apps-script/Code.gs) 내용을 그대로 붙여 넣은 뒤 저장합니다(Ctrl+S).
2. 위쪽 함수 목록에서 **`setup`** 을 고르고 **실행**을 누릅니다.
3. 권한 요청 창이 뜨면 **권한 검토 → 내 계정 선택**을 합니다.
   - “Google에서 확인하지 않은 앱” 화면이 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 누르고 **허용**합니다. 직접 만든 스크립트라서 나오는 안내이고, 이 스크립트는 `@OnlyCurrentDoc` 설정 때문에 **이 시트 하나만** 읽고 쓸 수 있습니다.
4. 시트로 돌아가면 **설정**·**명단** 탭이 생겨 있습니다. 설정 탭 B2의 6자리 숫자가 **수업 코드**입니다.

## 3. (선택) 명단 채우기

**명단** 탭의 A열에 학번, B열에 이름을 붙여 넣습니다. 나이스에서 내려받은 명단을 복사해도 됩니다.

- 명단을 채우면 **학번과 이름이 둘 다 명단과 맞아야** 제출됩니다. 오타나 장난 제출을 막아 줍니다.
- 비워 두면 명단 확인 없이 받습니다.

## 4. 웹 앱으로 배포하기

1. Apps Script 편집기 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 유형 선택(톱니바퀴)에서 **웹 앱**을 고릅니다.
3. 다음처럼 정하고 **배포**를 누릅니다.
   - 설명: `보고서 제출`
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
5. 확인: 복사한 주소를 시크릿 창에서 열어 `보고서 제출 주소가 작동하고 있어요.`가 보이면 성공입니다.

> **왜 ‘학교 도메인 사용자만’이 아니라 ‘모든 사용자’인가요?**
> 실험 사이트(Netlify)에서 구글로 보내는 요청에는 학생의 구글 로그인 정보가 실리지 않습니다. 그래서 학교 도메인으로 제한하면 학생 제출이 모두 실패합니다. 대신 **수업 코드**와 **명단**으로 아무나 제출하지 못하게 막습니다.
> 학교 Workspace 계정에서 ‘모든 사용자’ 항목이 보이지 않으면 관리자가 막아 둔 것입니다. 이때는 개인 Gmail 계정으로 1~4단계를 하면 됩니다.

## 5. 실험 사이트에 주소 넣기

[`src/submission-config.js`](../src/submission-config.js)의 따옴표 안에 웹 앱 URL을 넣습니다.

```js
export const SUBMIT_URL = 'https://script.google.com/macros/s/……/exec';
```

GitHub 웹에서 이 파일을 열고 연필(Edit) 버튼으로 고친 뒤 `main` 브랜치에 커밋하면 Netlify가 자동으로 다시 배포합니다. 주소가 비어 있으면 제출 칸이 나타나지 않습니다.

## 6. 수업에서 쓰기

- 수업 시작 때 칠판에 **수업 코드**를 적어 줍니다. 반이나 차시마다 설정 탭 B2를 다른 숫자로 바꿔도 됩니다.
- 학생은 설명까지 마친 뒤(마찰 전기처럼 실험이 둘이면 두 실험 모두) 퀴즈 아래에서 **사용 후기**(선택)를 쓰고, 수업 코드를 적고, 학번과 이름을 **비밀번호 확인처럼 두 번씩** 적습니다. 두 칸이 같아야 **[보고서 제출하기]** 버튼이 켜집니다. 확인 칸에는 붙여 넣기가 되지 않습니다.
- **[보고서 제출하기]** 를 누르면 바로 보내지 않고 **미리보기**가 열립니다. 학생은 학년·반·번호·이름, 실험별 예상·관찰·설명, 사용 후기를 확인한 뒤 **[최종 제출하기]** 를 눌러야 제출됩니다. **[수정하기]** 를 누르면 쓴 내용 그대로 돌아갑니다.
- 시트에 저장되었다는 답을 받아야만 **보고서 제출 완료**와 제출 시각이 나타나고, 그 보고서는 다시 낼 수 없으며 글도 잠깁니다(새로 고침해도 유지). 다시 해야 하면 학생이 **기록 지우고 처음부터**를 눌러 새 보고서로 내면 됩니다.
- 제출을 마감하려면 설정 탭의 **제출 받기** 체크를 해제합니다.
- ‘처음부터’ 다시 해서 낸 새 보고서는 새 줄로 남고 **제출 횟수** 칸에 몇 번째인지 적힙니다. 보통 가장 마지막 줄을 보면 됩니다.

### 같은 보고서가 두 번 저장되지 않아요

- 보고서마다 **제출 ID**를 하나 정해 함께 보냅니다(시트 맨 오른쪽 숨긴 열 `제출 ID`).
- 버튼을 여러 번 누르거나, 인터넷이 끊겨 학생이 다시 누르거나, 시트에는 저장됐는데 학생 화면에 답이 오지 않아 다시 눌러도 **같은 제출 ID**라서 새 줄을 만들지 않고 처음 저장한 결과를 돌려줍니다.
- 다른 학생의 보고서나 ‘처음부터’ 다시 한 새 보고서는 제출 ID가 달라서 막지 않습니다.
- 여러 학생이 동시에 내도 스크립트 잠금(LockService)으로 한 번에 하나씩 저장합니다.

### 반별로 모아 보기

학번은 **숫자 5자리**(학년 1자리 + 반 2자리 + 번호 2자리)로 받습니다. 제출 순서와 상관없이 각 실험 탭 안에서 이렇게 정리됩니다.

```
1행  보기 순서 → ☐ 학번 순  ☑ 제출 시각 순     ← 정렬 버튼(체크박스)
2행  제출 시각 | 반 | 학번 | 이름 | …          ← 머리글
     1반 학생들                                  ← 1반 색
     (빈 줄)
     2반 학생들                                  ← 2반 색
     (빈 줄)
     … 10반 · (빈 줄) · 11반
```

- **정렬 버튼:** 1행의 **학번 순** 또는 **제출 시각 순** 체크박스를 누르면, 반별로 모인 채 반 안에서 그 순서로 다시 정리됩니다. 하나만 체크되고, 새로 들어오는 보고서도 그 순서에 맞춰 들어갑니다. 위쪽 메뉴 **보고서 정리**에도 같은 기능과 ‘모든 실험 탭 반별로 다시 정리’가 있습니다(메뉴는 Apps Script를 저장한 뒤 시트를 새로 고치면 보여요).
- 반은 **숫자 순서**(1, 2, … 10, 11)로 정리합니다. 시트의 기본 정렬은 글자 순서라서 ‘10반’, ‘11반’이 ‘1반’ 바로 뒤에 붙고 빈 줄이 사라질 수 있는데, 다음 제출이나 정렬 버튼을 누를 때마다 처음부터 다시 정리하므로 바로잡힙니다.

- 반마다 줄 색이 다릅니다. 1반 분홍 → 주황 → 노랑 → 연두 → 초록 → 민트 → 하늘 → 파랑 → 남색 → 보라 → 11반 자주 순서의 파스텔 무지개이고, 12반부터는 회색입니다.
- 오른쪽 빈 칸에 선생님 메모(점수, 피드백 등)를 적어도 다시 정리할 때 그 줄과 함께 움직입니다. 다만 칸에 직접 칠한 색은 반 색으로 다시 칠해집니다.

### 시트에 저장되는 칸

| 칸 | 내용 |
|---|---|
| 제출 시각, 반, 학번, 이름, 제출 횟수 | 누가 언제 냈는지. 반은 학번 2~3번째 자리로 정해요(20315 → 3반) |
| 예상, 예상한 까닭 | 처음 고른 보기와 까닭(관찰 뒤에 고칠 수 없음) |
| 관찰, 설명 | 학생이 저장한 관찰 기록과 제출 때의 설명 |
| `[풍선과 털] 예상` … `[숟가락과 장갑] 설명` | 실험이 둘인 페이지(마찰 전기)는 실험마다 예상·까닭·관찰·설명 칸이 따로 생겨요 |
| 사용 후기 | 학생이 쓴 시뮬레이션 사용 후기(선택). 과학 설명과 따로 저장해요 |
| 제출 ID (숨김) | 같은 보고서가 두 번 저장되지 않게 하는 번호 |

퀴즈 결과는 학생이 스스로 확인하는 활동이라 보내지 않습니다.

## 코드를 고쳤을 때

`Code.gs`를 고친 뒤에는 **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**를 눌러야 반영됩니다. 이렇게 하면 웹 앱 주소가 그대로 유지됩니다. **새 배포**를 다시 만들면 주소가 바뀌므로 5단계를 다시 해야 합니다.

새 실험을 추가해도 `Code.gs`는 고치지 않아도 됩니다. 실험 페이지 제목(예: `옴의 법칙 실험실` → `옴의 법칙`)으로 탭이 저절로 생깁니다.

지난 버전이 만든 탭(1행이 바로 `제출 시각 | 반 | 학번 …` 머리글)은 메뉴·정렬 버튼을 누르거나 새 보고서가 들어올 때 **그 자리에서 새 모양으로 바뀝니다**(맨 위에 정렬 버튼 줄을 끼워 넣고 `사용 후기`·`제출 ID` 칸을 더함, 데이터는 그대로).
실험 수가 달라 칸 구성이 맞지 않는 탭(예: 마찰 전기가 실험 하나였을 때 만든 탭)은 지우지 않고 `마찰 전기 (이전)`처럼 이름을 바꿔 두고 새 탭을 만듭니다. 필요 없으면 지워도 됩니다.

> 새로 들어온 보고서가 계속 예전 모양(정렬 버튼 줄 없음)으로 쌓인다면, 웹 앱이 아직 예전 버전으로 배포되어 있는 거예요. **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**를 해 주세요. 코드를 저장만 하면 메뉴는 바뀌지만 학생 제출은 배포된 버전이 처리해요.

`Code.gs`를 아직 바꾸지 않았더라도 새 실험 페이지에서 낸 보고서는 저장됩니다. 마찰 전기의 두 실험 답은 예전 칸(예상·관찰·설명)에 `[풍선과 털] …` `[숟가락과 장갑] …`처럼 한 칸에 이어서 들어가고, 사용 후기와 중복 방지는 `Code.gs`를 바꾼 뒤부터 적용됩니다.

## 개인정보와 한계

- 학생 글은 선생님 시트에만 저장되고, 실험 사이트 서버는 아무것도 보관하지 않습니다.
- 브라우저는 새로 고침해도 글이 사라지지 않도록 예상·관찰·설명, 퀴즈 답, 사용 후기, 수업 코드, 제출 완료 여부를 **그 탭이 닫힐 때까지만**(sessionStorage) 기억합니다. 탭을 닫으면 지워집니다.
- 학번과 이름은 기억하지 않고 매번 새로 적습니다(함께 쓰는 컴퓨터에서 앞 학생 이름으로 제출되지 않도록).
- 시트 공유 링크를 학생에게 주지 마세요. 학기가 끝나면 시트를 정리하세요.
- 학생 구글 로그인으로 본인 확인을 하는 방식이 아니어서, 수업 코드와 친구의 학번·이름을 아는 학생은 친구 이름으로 낼 수 있습니다. 제출 시각과 제출 횟수가 남으므로 이상한 제출은 시트에서 확인할 수 있습니다.
- 학생 글이 `=`, `+`, `-`, `@`로 시작해도 수식으로 실행되지 않도록 글자로 저장합니다.

## 개발자용: 시험해 보기

`npm test`는 `apps-script/fake-google.js`의 가짜 시트 환경에서 `Code.gs`의 저장·코드 확인·명단 확인·반별 정리(10반·11반 포함)·정렬 버튼·중복 방지를 시험합니다. `tests/friction.spec.js`는 브라우저에서 제출 주소를 가로채 같은 `Code.gs`로 처리하며 미리보기·최종 제출·재시도·새로 고침 시나리오를 확인합니다.
